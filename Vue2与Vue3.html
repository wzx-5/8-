A

韦恩图总览：Vue2 与 Vue3 的关系

三个圈就是全部考点框架：向左（红）= Vue2 独有，向右（蓝）= Vue3 独有，中间（绿）= 两版共有。

韦恩图：核心结论 —— Vue3 不是推倒重来，而是"底层响应式重写 + 编译优化 + 提供组合式新写法"，模板/组件/路由等骨架完全继承。
一句话总结关系：Vue3 = Vue2 的 升级内核（Proxy 响应式 + 更快 diff + 编译优化） + 新增风格（Composition API），同时保留大部分 Vue2 语法（Options API 兼容、模板指令不变），迁移成本主要在 API 层而非模板层。
B

Vue2 核心要点

① 响应式原理与三大局限（必背）

核心：初始化时递归遍历 data 每个 key，用 Object.defineProperty 劫持 get/set。get 时收集依赖（Dep 存 Watcher），set 时派发更新。

  • 局限 1：无法侦测属性"新增/删除" → 必须用 Vue.set(obj, key, val) / vm.$set（删除用 Vue.delete）；
  • 局限 2：无法侦测"数组下标赋值"和 length 修改 → 重写 7 个变更方法 push/pop/shift/unshift/splice/sort/reverse 触发更新；
  • 局限 3：对象要递归劫持，深层嵌套对象初始化性能差。
常见场景：① 动态给 this.xxx.新字段 = 1 页面不更新 → 用 $set；② 直接 this.arr[0] = 1 不更新 → 用 splice(0,1,1) 或 $set。数组元素若是对象仍会被递归响应式化。

② 生命周期（8 + 2 钩子）

阶段钩子要点 / 面试点
创建beforeCreate → createdbeforeCreate 拿不到 data；created 可拿 data，适合发初始请求（此时 DOM 未渲染）
挂载beforeMount → mountedmounted 时 DOM 就绪，适合操作 DOM / 初始化 echarts
更新beforeUpdate → updated数据变化 → DOM 更新前后；updated 里改数据会死循环
销毁beforeDestroy → destroyedbeforeDestroy 里清理定时器 / 移除监听 / $off，防内存泄漏
缓存activated / deactivated配合 keep-alive，组件切换不销毁而是"激活/失活"
错误errorCaptured捕获子孙组件错误，可用于全局错误上报
created vs mounted：created 在渲染前（拿不到 DOM），mounted 在渲染后（能操作 DOM）。发请求两者都行，但要看"要不要依赖渲染结果"。

③ 组件通信 8 法（面试必聊）

方式方向使用场景
props / $emit父子最常用，父传子用 props，子通知父用 emit
$refs父 → 子直接拿子组件实例调方法（跨层不推荐）
$parent / $children父子不推荐，耦合高；Vue3 已移除 $children
$attrs / $listeners祖先 → 后代透传未声明为 props 的属性 / 事件（写高阶组件）
provide / inject跨层级祖先注入，后代任意深度取用；默认非响应式（2.x）
EventBus任意$on/$emit/$off 兄弟/任意通信；记得 beforeDestroy 里 $off，否则内存泄漏
Vuex全局跨页面/多组件共享状态，严格单向数据流
slot父 → 子父组件向子组件分发结构（默认/具名/作用域）

④ v-model 与 .sync（都是语法糖）

  • v-model 默认对应 value prop + input 事件（组件上要自己声明）；
  • .sync 对应 update:xxx 事件，用于"修改多个 prop"；2.6 之后与 v-model 概念统一。
// 自定义组件实现 v-model
Vue.component('my-input', {
  props: ['value'],
  template: '<input :value="value" @input="$emit(\'input\', $event.target.value)" />'
})

⑤ v-for 与 v-if 优先级 / key

  • Vue2 中 v-for 优先级高于 v-if：先循环再判断，浪费性能，且 v-if 拿不到 v-for 变量时直接报错；
  • 最佳实践：把 v-if 放外层，或用计算属性过滤后再 v-for；
  • key 用唯一稳定 id，不要用 index（头部插入会错位复用，输入框内容串位）。

⑥ $nextTick 与异步更新

数据变化 → Watcher 去重后进队列 → 微任务里统一冲刷（Vue2.5+ 用 Promise，兼容降级 MutationObserver / setImmediate / setTimeout）。$nextTick 回调排在冲刷之后，所以能拿到更新后的 DOM。

常见场景：① v-if 显示元素后立刻操作该 DOM；② created 里拿渲染结果；③ 批量改多个数据只触发一次更新。

⑦ 指令 / 过滤器 / 插槽 / mixin

  • filters：模板管道语法 {{ val | format }}，全局/局部注册；Vue3 已移除；
  • slot：默认插槽 + 具名插槽 <template #header>（2.6 后统一 v-slot）+ 作用域插槽 slot-scope="props"；
  • mixin：选项合并规则 —— data 组件优先；生命周期钩子 mixin 先执行、组件后执行；同名 methods 组件覆盖 mixin；
  • 自定义指令：钩子 bind / inserted / update / componentUpdated / unbind（Vue3 改名）。

⑧ 全局 API 与实例 API 清单（Vue3 大改的部分）

全局：Vue.use / Vue.component / Vue.directive / Vue.mixin / Vue.extend / Vue.nextTick / Vue.set / Vue.delete / Vue.prototype.xxx
实例：$on / $off / $emit / $once / $refs / $attrs / $listeners / $parent / $children / $nextTick / $set / $delete
迁移重点：这些 API 在 Vue3 中几乎全部"应用级化"（app.component / app.use / app.config.globalProperties），$on/$off/$once、$children 直接移除。
C

Vue3 核心要点

① 响应式：Proxy + 懒代理（必背）

  • 用 new Proxy(target, handler) 代理整个对象，拦截 get / set / deleteProperty / has / ownKeys；
  • 懒代理：只有 get 到某个属性时才用 Reflect.get 拿到结果并递归代理，初始化不递归，性能更好；
  • 新增/删除属性、数组下标、length、Map/Set 都能侦测 → 不需要 $set，也不需要重写数组方法；
  • 局限：不能代理基本类型（要用 ref）；Proxy 无法在 IE11 使用（Vue3 放弃 IE11）。
// Vue3 响应式核心（简版）
function reactive(target) {
  return new Proxy(target, {
    get(t, k, r) {
      track(t, k)                       // 收集依赖
      const res = Reflect.get(t, k, r)
      return typeof res === 'object' && res !== null ? reactive(res) : res // 懒递归
    },
    set(t, k, v, r) {
      const old = Reflect.get(t, k, r)
      const ok = Reflect.set(t, k, v, r)
      if (old !== v) trigger(t, k)      // 派发更新
      return ok
    },
    deleteProperty(t, k) {
      const had = Reflect.has(t, k)
      const ok = Reflect.deleteProperty(t, k)
      if (had) trigger(t, k)            // 删除也能触发
      return ok
    }
  })
}

② Composition API 全家桶

  • setup(props, ctx) 在 beforeCreate 之后、created 之前执行，是组合式入口；
  • ref（基本类型，JS 里要 .value，模板自动解包）/ reactive（对象）/ computed / watch / watchEffect；
  • 生命周期用 onMounted / onUnmounted 等；响应式数据跨组件复用用 provide / inject（Vue3 默认响应式）；
  • toRefs / toRef 保解构响应性；shallowRef / shallowReactive / readonly 做性能优化；
  • script setup 语法糖（3.2+）：顶层变量直接用，defineProps / defineEmits / defineExpose / withDefaults 免 import。
<script setup>
import { ref, computed, onMounted } from 'vue'
const count = ref(0)                       // 模板里直接用 count，不用 .value
const double = computed(() => count.value * 2)
const props = defineProps({ title: String })
const emit = defineEmits(['change'])
onMounted(() => console.log('mounted', props.title))
</script>

④ v-model 新语法

  • 默认 prop：value → modelValue；默认事件：input → update:modelValue；
  • 支持一个组件多个 v-model：v-model:title + v-model:content；
  • 支持自定义修饰符（3.4+ 可用 defineModel 简化）；
  • .sync 被 v-model:xxx 替代。
// 子组件：多 v-model + 修饰符
props: { modelValue: String, title: String, modelModifiers: { default: () => ({}) } }
// 父组件
<Child v-model="msg" v-model:title="title" />

⑥ 编译优化：Vue3 为什么快

  • patchFlag：编译时给动态节点打标记，diff 时只对比"有变化的属性"，静态内容直接跳过；
  • 静态提升（hoistStatic）：完全静态的节点只创建一次、被复用，不参与更新；
  • 事件缓存（cacheHandlers）：绑定事件缓存复用，避免重复创建内联函数；
  • Block Tree：把动态子节点收集到 block，diff 时跳过整棵静态子树。

⑧ 组合式函数 composables 与 Pinia

  • composables：把"状态 + 副作用"抽成 useXxx() 函数，显式传参返回，解决 mixin 的命名冲突与来源不透明，天然支持 TS 推导；

面试必背问答（28 题）

每题先背"🗣️ 背这句"的口语答案，再记"🔑 要点"和"💡 口诀"。

1. Vue2 响应式原理？有什么局限？🔥必考
核心是 Object.defineProperty：初始化时递归遍历 data 每个属性劫持 get/set，get 收集依赖（Dep→Watcher），set 派发更新。局限：① 侦测不到新增/删除属性；② 侦测不到数组下标赋值和 length；③ 递归劫持性能差。
  • 新增/删除 → 用 Vue.set / Vue.delete；
  • 数组 → 重写 7 个变更方法，下标赋值要用 splice。
"defineProperty = 属性级 + 要递归 + 新增删除数组有盲区。"
2. Vue3 为什么用 Proxy 代替 defineProperty？🔥必考
Proxy 代理整个对象，能拦截 get/set/deleteProperty/has/ownKeys，所以新增/删除属性、数组下标、length、Map/Set 全能侦测，不用 $set 和数组 hack。而且是懒代理：只有 get 到才递归代理，初始化不递归，性能更好。
  • defineProperty 代理的是"属性"（遍历+递归）；Proxy 代理的是"对象"（惰性+全能）；
  • Proxy 不能用 polyfill，所以 Vue3 放弃 IE11；
  • 配合 Reflect 保证 this 指向正确。
"Proxy = 整对象 + 懒代理 + 全能拦截；defineProperty = 单属性 + 递归 + 有盲区。"
3. ref 和 reactive 的区别？怎么选？🔥必考
ref 主要处理基本类型（底层其实是 reactive 包一层 {value}），模板自动解包、JS 里要 .value；reactive 只能代理对象/数组，不能代理基本类型。
  • 基本类型用 ref，复杂对象用 reactive；
  • reactive 解构会丢响应性 → 用 toRefs；
  • 现在官方更推荐"全用 ref"（3.4+ 自动解包更友好）。
"ref 管基本类型要 .value，reactive 管对象，解构要 toRefs。"
4. Vue3 为什么比 Vue2 快？🔥必考
四个原因：① 响应式用 Proxy 懒代理，初始化不递归所有属性；② 编译期优化——patchFlag 只标记并对比动态节点、静态提升（静态节点只创建一次）、事件缓存、Block Tree；③ diff 更快——快速 diff + 最长递增子序列，移动次数最少；④ tree-shaking 按需引入，包更小。
  • patchFlag：编译时打标记，运行时跳过静态对比；
  • 静态提升：静态 VNode 创建一次复用；
  • cacheHandlers：事件处理函数缓存复用。
"懒响应式 + 编译优化(patchFlag/静态提升/事件缓存) + 更优 diff + tree-shaking。"
5. Vue2 和 Vue3 的 diff 有什么区别？🔥必考
相同：都是同层比较、都用 key 优化、复杂度都是 O(n)。不同：Vue2 用双端比较（oldStart/oldEnd/newStart/newEnd 四个指针两端交叉比较）；Vue3 先去掉头尾相同的公共部分，剩余 keyed 部分用最长递增子序列计算最小移动，DOM 移动更少更快。
"V2 双端四指针；V3 头尾先清 + LIS 最少移动。"
6. watch 和 watchEffect 的区别？🔥必考
watch 是"指定源 + 回调"，显式声明监听谁，能拿到新旧值，默认惰性（不立即执行，除非 immediate），支持 deep；watchEffect 自动收集依赖，回调里访问了哪些响应式数据就监听哪些，立即执行一次，拿不到新旧值。
"watch 显式有新旧值默认懒；watchEffect 自动收集立即跑无新旧值。"
7. computed 和 watch 的区别？
computed 有缓存（依赖不变不重算），用于派生数据，声明式；watch 是命令式监听副作用（发请求、操作 DOM、处理异步），支持 deep/immediate。能用 computed 就别用 watch。
"computed 缓存派生数据，watch 监听副作用。"
8. Vue3 中 v-model 有哪些变化？🔥必考
① 默认 prop 由 value 改为 modelValue，事件由 input 改为 update:modelValue；② 支持一个组件多个 v-model（v-model:title 等）；③ 支持自定义修饰符（defineModel / props.modifiers）；④ .sync 被 v-model:xxx 替代。
"value→modelValue，input→update:modelValue，可多个，替代 .sync。"
9. 组件通信方式有哪些？（V2 / V3 分别说）🔥必考
V2：props/$emit、$refs、$parent/$children、$attrs/$listeners、provide/inject、EventBus、Vuex、slot。V3：props/emit、defineExpose+ref、provide/inject（响应式）、Pinia、mitt（替代 EventBus）、$attrs（含原 $listeners）、slot。
"props 父子、refs 拿实例、inject 跨层、EventBus 兄弟、Vuex/Pinia 全局。"
10. Vue2 如何监听数组变化？为什么不能直接拦截下标？
重写了 push/pop/shift/unshift/splice/sort/reverse 7 个方法，调用时先执行原方法再触发更新。不直接拦截下标是因为给每个元素 defineProperty 成本高、数组大时性能差，Vue 选择放弃。改下标用 $set 或 splice。
"7 方法重写，下标赋值要用 $set/splice。"
11. $nextTick 原理？为什么能拿到更新后的 DOM？🔥必考
数据变化 → Watcher 去重进队列 → 在微任务中统一冲刷（Vue2.5+ 用 Promise，兼容降级 MutationObserver/setImmediate/setTimeout）。nextTick 回调排在冲刷之后，所以能拿到更新后的 DOM；它也返回 Promise，可 await。
"更新进队列→微任务批量冲刷→nextTick 排在后面执行。"
12. key 的作用？为什么不建议用 index？🔥必考
key 是 VNode 在 diff 时的身份标识，决定节点是"复用/移动"还是"新建/删除"。用 index 做 key 的坑：数组头部插入时后面所有元素 key 都变，导致内容错位复用（比如输入框的值串到别的行），全部重新渲染。
"key 是身份证；index 会搬家导致错位复用，用唯一 id。"
13. v-for 和 v-if 优先级？为什么不能同时用？
Vue2 中 v-for 优先于 v-if（先循环再判断，白白多判断，且 v-if 访问不到 item 会报错）；Vue3 中 v-if 优先于 v-for（先判断再循环，item 未定义报错）。最佳实践：v-if 放外层，或用计算属性先过滤。
"V2 先 for 后 if，V3 先 if 后 for，都会踩坑 → 用计算属性过滤。"
14. Vue2 迁移到 Vue3 要注意什么？🔥必考
① filters 移除（用 computed/方法）、$on/$off 移除（用 mitt）、$children 移除；② v-model 改 modelValue；③ 全局 API 改应用级（Vue.use→app.use、Vue.prototype→app.config.globalProperties）；④ 钩子改名 beforeDestroy→beforeUnmount、destroyed→unmounted；⑤ 异步组件用 defineAsyncComponent；⑥ .sync 改 v-model:xxx。
"filters/$on 删了、v-model 改名、全局 API 收进 app、钩子改名、async 组件换写法。"
15. 为什么 Vue3 移除 filters 和事件总线？
filters 的管道语法与 JS 割裂、调试困难、与 computed/methods 功能重叠、不利于 tree-shaking，官方建议用计算属性/方法。事件总线依赖 $on/$off 实例 API，在 Vue3 中与组合式响应式系统不配套，且跨组件通信隐性依赖难追踪，官方推荐 mitt 或 Pinia。
"filters 与 JS 割裂、总线难追踪 → 都砍，用更显式的方式。"
16. Teleport 的使用场景？
把组件 DOM 渲染到指定容器（如 body），脱离父级 DOM 层级。场景：模态框/弹窗（摆脱父级 overflow:hidden、z-index 层级困住）、通知/悬浮提示、全屏 loading、以及需要传送到指定挂载点的情况。
"弹窗、通知、悬浮层 → Teleport 传送到 body。"
17. 虚拟 DOM 是什么？为什么要它？🔥必考
VNode 是真实 DOM 的轻量 JS 对象描述。好处：① 跨平台（可自定义渲染器渲染到任意目标）；② 通过 diff 最小化 DOM 操作，避免频繁重排重绘；③ 声明式开发，不用手动操作 DOM。代价是内存与对比开销，所以 Vue3 用编译优化缩小 diff 范围。
"VNode = DOM 的 JS 描述，换来跨平台 + 最小化更新。"
18. mixin 有什么缺点？组合式函数怎么解决的？🔥必考
mixin 缺点：命名冲突（属性/方法合并时覆盖）、来源不透明（数据不知道从哪来）、复用单元是配置项不灵活、多个 mixin 叠加难维护。组合式函数 useXxx() 显式传参、显式返回，天然解决冲突，逻辑内聚、利于 TS 推导。
"mixin 命名冲突 + 来源不透明；composable 显式传参返回，逻辑内聚。"
19. setup 什么时候执行？为什么 Vue3 没有 beforeCreate/created？⚠️易错
setup 在组件实例创建后、渲染前执行（beforeCreate 之后、created 之前）。Vue3 把 beforeCreate/created 合并进 setup（setup 里能直接拿 props/context），所以没有这两个钩子，其余钩子用 onXxx 注册。
"setup 顶替 beforeCreate/created，是组合式入口。"
20. reactive 解构后为什么丢响应性？怎么解决？
解构拿到的是值拷贝，脱离了 Proxy 代理，后续赋值只是普通变量。解决：用 toRefs 把每个属性转成 ref（模板自动解包可直用），单个属性用 toRef；只读用 readonly。
"解构 = 值拷贝脱离代理；toRefs 保响应。"
21. keep-alive 的原理？有哪些钩子？
keep-alive 是内置组件，缓存组件实例与 VNode，切换时组件不销毁而是"失活"，恢复时不重建而是"激活"。钩子：activated / deactivated（V3 中 onActivated/onDeactivated）。include/exclude 按 name 缓存，max 限制缓存数量（LRU 淘汰）。
"keep-alive = 缓存实例不销毁，LRU 淘汰，激活/失活钩子。"
22. 手写 Vue2 的 defineReactive 核心？🖊️手写常考
function defineReactive(obj, key, val) {
  observe(val)                       // 递归：子对象也变响应式
  const dep = new Dep()              // 每个 key 一个依赖容器
  Object.defineProperty(obj, key, {
    get() {
      if (Dep.target) dep.add(Dep.target)   // 收集当前 watcher
      return val
    },
    set(newVal) {
      if (newVal === val) return
      val = newVal
      observe(newVal)                // 新值也做响应式
      dep.notify()                   // 通知 watcher 更新
    }
  })
}
"定义在属性上，get 收集、set 派发，赋值新值再 observe 一次。"
23. 手写 Vue3 reactive（Proxy 简版）？🖊️手写常考
function reactive(target) {
  return new Proxy(target, {
    get(t, k, r) {
      track(t, k)                    // 收集依赖
      const res = Reflect.get(t, k, r)
      return typeof res === 'object' && res !== null
        ? reactive(res) : res        // 懒递归：用到了才代理
    },
    set(t, k, v, r) {
      const old = Reflect.get(t, k, r)
      const ok = Reflect.set(t, k, v, r)
      if (old !== v) trigger(t, k)   // 派发更新
      return ok
    },
    deleteProperty(t, k) {
      const had = Reflect.has(t, k)
      const ok = Reflect.deleteProperty(t, k)
      if (had) trigger(t, k)         // 删除也能触发
      return ok
    }
  })
}
"代理整对象 + get 时懒递归 + 新旧值比较再触发。"
24. Vue3 的异步渲染与 nextTick 是什么关系？
响应式数据变化后，effect 不立即执行，而是被调度器放进 job 队列去重，在微任务中批量 flush，这就是异步批量更新。nextTick 回调在 flush 之后执行，所以"改数据 → nextTick 里读 DOM"拿到的一定是更新后的。
"改动进队列 → 微任务批量冲刷 → nextTick 排在冲刷后。"
25. shallowRef / shallowReactive / triggerRef 是什么？
浅层响应式：只代理第一层，深层保持原值，适合大对象/大列表（不需要深层监听时）做性能优化。shallowRef 改 .value 才触发，深层属性变化不触发，需手动 triggerRef 强制刷新。
"浅层 = 只响应第一层，改深属性要手动 triggerRef。"
26. 选项式还是组合式？团队新项目怎么选？
小项目、简单组件、团队只熟 V2，选项式也完全可用；新项目、复杂逻辑、长组件、要复用和 TS 支持，推荐组合式（script setup）。两者可混用，Vue3 官方推荐组合式，但选项式完全兼容。
"简单用选项式，复杂/新项目用组合式，两者可混用。"
27. v-if 和 v-show 的区别？怎么选？🔥必考
v-if 是真正创建/销毁 DOM（有懒加载效果，切换有销毁重建开销）；v-show 是 display:none 切换（元素常驻，切换只改样式）。高频切换用 v-show，运行时条件几乎不变 / 要懒加载用 v-if。
"v-if 增删 DOM、v-show 只切 display；高频切换选 v-show。"
28. Vue2 中 data 为什么必须是函数？
因为组件是可复用的：如果 data 是对象，所有实例共享同一引用，一处修改处处变。写成函数每次实例化都返回全新对象，保证每个组件实例数据独立。（根实例 new Vue 可以不用函数。）
"data 函数返回新对象 = 每个组件实例数据隔离。"

易错点快筛

全是面试官挖坑的点，考前扫一遍。

V2 数组下标赋值不更新：arr[0]=1 无效，用 $set/splice
V2 新增属性不更新：obj.newKey=1 无效，用 Vue.set
v-for 与 v-if 优先级：V2 先 for 后 if；V3 先 if 后 for，方向相反
ref 在 JS 里忘 .value：模板自动解包，JS 中必须 ref.value
reactive 不能代理基本类型：字符串/数字要用 ref
reactive 解构丢响应性：要 toRefs 保住
生命周期改名：beforeDestroy→onBeforeUnmount、destroyed→onUnmounted
v-model 默认属性：V2 是 value/input，V3 是 modelValue/update:modelValue
filters 在 V3 没了：别再说"Vue3 用 filters 格式化"，用 computed
事件总线在 V3 没了：$on/$off 已移除，用 mitt/Pinia
Proxy 兼容性：Vue3 不支持 IE11（defineProperty 才支持）
watch 默认不立即执行：要立即执行加 immediate:true；对象深度监听加 deep:true
